## 項目1: 付け札D&D不能（メインが原因特定済み — 再現診断データあり）
### 診断結果（メイン実測）
- ドラッグ中の `dropTargetAt` は正しく `{kind:'meld'}` を返す（attachableMelds・レイキャストは健全）
- しかし当該メルドの投影スクリーン座標が y=861〜976（ビューポート720・手札帯top=479）と**手札帯より下**にあり、`resolveDrop` の先頭ガード `if (y >= handTop - 6) return false // 並び替え扱い` に食われて attach が発火しない
- 真因: R12（meldLayout 再設計）で自席メルドが外周方向=画面下端側へ配置され、ドロップ受理可能な画面領域（handTop より上）から外れた
- 注意: メインの計測は hidden ペインでカメラが goal へ settle していない状態。実ユーザーのカメラでも同種の症状が出ている（ユーザー報告）。修正時は**カメラを goal へ手動 settle してから検証**すること（過去エージェントの前例あり: __cameraState 等）

### 修正要求（両方满たすこと）
1. **自席メルドの可視域配置**: 既定カメラ（2〜6人・縦/横）で自席メルドが**手札帯より上の可視領域に投影される**よう layoutSeatMelds / 席別パラメータを調整（例: 自席のみ u を控えめにして横展開・スケール縮小を優先。R12の中央保護・隣席不可侵の制約は維持）
2. **resolveDrop / moveDrag のガード改善**: 手札帯の y ガードで 3D メルド標的への正当なドロップを弾かない構造にする（例: y >= handTop でも「ポインタ直下が手札ファンのカード上でない かつ dropTargetAt が meld を返す」なら付け札を受理。並び替え誤発火・ゴースト自身の elementFromPoint 干渉に注意）
- 検証: 実プレイ相当の自動化（単独7公開→両者メルド保有→付け札ドラッグ→手札減少とメルド成長）で成立を確認し報告。メインの再現スクリプト方式（合成 pointer+__dropProbe グリッド）を参考にしてよい
