# 契約11: メルド配置の再設計 — 中央ゾーン不可侵

委譲先: implementer-opus / ダイヤル: ゴール委譲

## 目的
- 要求（ユーザー原文+スクリーンショット2枚）: 「山札や捨て札に、手元のメルドが重なって表示される場合があります（たくさんメルドを公開すると二行になって表示が重なるようです）重複しないようにカードの大きさを変えるなり位置を変えるなり、配置を変えるなりいい感じの仕組みにするなどしてほしいです」
- 観測事実: メルドの段折返し（半径方向の内側へ積む方式）が、メルド数の増加で卓中央の山札/捨て札ゾーンに侵食し、山札の上にメルドが重なって表示される。メルド同士も段間で重なって見える
- ゴール: **メルドがいくつ公開されても、山札・捨て札・他席のメルドと視覚的に重ならない**配置システム
- 成功条件: 合格基準の全コマンド exit 0 + 極端ケースの配置検証報告（status行必須）

## 設計要求（方式は委ねる。満たすべき制約のみ）
1. **中央保護ゾーン**: 山札・捨て札の周囲（半径 r_center 程度）へはメルドが絶対に入らない
2. **席間の不可侵**: 隣席のメルド領域と重ならない（6人卓・全員が多数メルド公開の最悪ケースで検証）
3. **スケール適応**: 席の領域に収まらない場合はメルドカードのサイズを段階的に縮小してでも収める（ユーザー提案の「大きさを変える」を許容。ただし最小でも読める下限を設ける — R8で拡大した文字が活きる範囲）
4. **整列の美しさ**: 同一席のメルドは整然と（行内ギャップ・段間ギャップの視覚余白を確保。現状の「段間で重なって見える」を解消）
5. **追従**: meldCentroid（付け札ドロップ標的・光枠）・meldIdAt レイキャストが新配置に正しく追従
6. 付け札でメルドが伸びた場合（最長13枚シークエンス）も破綻しない（折返しや縮小で吸収）
