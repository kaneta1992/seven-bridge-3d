# 契約16: NPCプレイヤー — 1人プレイと人間+NPC混成

委譲先: implementer-opus / ダイヤル: ゴール委譲

## 目的
- 要求（ユーザー原文）: 「任意の数NPCを追加して一人でも、人間2NPC2で遊べるようにしたいです」
- ゴール: ①ロビーから人間1+NPC1〜5の1人プレイを開始できる ②通信対戦の待機ルームでホストがNPCを追加/削除し、人間+NPC混成で開始できる
- 成功条件: 合格基準の全コマンド exit 0 + 動作確認報告（status行必須）

## 実装要求
1. **ボットAI（共通モジュール）**: view（PlayerView相当の情報）から着手を決める純粋なロジック。強さは「実用的」:
   - 公開できるメルドは公開する / 付け札できるなら付ける（自分の失点を減らす）
   - 鳴き: 手が進むなら行う（毎回ではなく妥当な判断。例: メルドが完成する・手札が減る場合）
   - 捨て札: 失点の高い孤立カード優先などの簡単なヒューリスティック
   - 思考時間: 0.8〜1.6s程度のランダム待ち（人間らしいテンポ・鳴きウィンドウ内に収まること）
2. **1人プレイ**: ロビーのホットシートタブを拡張（または専用導線）— 各席を人間/NPCに指定（既定: 自分1+NPC n）。NPC手番はボットが自動で打ち、視点・カメラは人間プレイヤー固定（NPC手番で視点交代しない。ホットシートの手番カメラリセットは人間席のみに）。NPCの手札は人間に見せない（3D浮遊手札=裏面のまま）
3. **通信対戦のNPC**: 待機ルームにホスト専用「NPCを追加/削除」UI。名簿にNPC表示（例: 「NPC・ボブ」）。開始時にNPC込みで席確定。**NPCの着手はホストクライアントがボットAIで生成し、権威エンジンへ直接適用**（なりすまし検証と衝突しない実装に）。ゲスト側からはNPCが普通のプレイヤーに見える（スナップショットに自然に乗る）
4. **NPC名**: 日本語の親しみやすい名前プール（例: ロボ太/カル子/ジャック等）+「NPC」表記が分かる印
5. **整合**: スコア票・勝敗・親ルール・鳴き優先・切断処理（NPCは切断しない）・公開ルーム広告のcount（NPC込み人数）が自然に動作

## 不変条件（違反=不合格）
- src/core 非改変。ボットはエンジンの公開API（applyAction等をドライバ経由で）だけを使う
- 視界の公正: ボットの判断入力は「そのNPC席の deriveViewFor 相当」に限定（他家の手札を覗くAIにしない）。ホスト権威実装の都合で全状態にアクセス可能でも、判断関数への入力を絞ること
- E5（ネットワークに他家手札を流さない）・E7/E8（なりすまし・二重接続）等の既存テスト性質を維持

## エッジケース
- E1: 人間1+NPC5 / 人間2+NPC2 / NPCだけが鳴き合う連鎖 / NPCの上がり・流局・親継続
- E2: 通信対戦でホストがNPC追加→ゲスト入室→開始の順序 / 満席(6)でのNPC追加拒否 / NPC削除
- E3: NPC手番中に人間が切断・復帰しても進行が壊れない / ホットシートの一時停止（タブ非表示）から復帰してもNPCの多重着手がない
- E4: 鳴きウィンドウ: NPCが鳴くか見送るかの判断がタイマー満了(10s)前に必ず確定する
