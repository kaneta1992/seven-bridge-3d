## アーキテクチャ要求（凍結事項 — 内部実装は自由）
- **ホスト権威**: ルーム作成者のクライアントのみがエンジン(applyAction)を実行。ゲストはアクション要求を送信し、ホストが検証・適用
- **視界フィルタ配信**: ホストは各ピアへ `deriveViewFor(state, そのプレイヤー)` 相当のみ送信。他家の手札・山札の中身をネットワークに流さないこと
- 状態同期はフィルタ済み全量スナップショット（差分同期にしない — 要件§3.1）
- 鳴きウィンドウのタイマーはホストが管理（満了で自動パス）。ゲストには残り時間を含めて配信
- ルームコード: 英数6桁を生成・入力で参加。日本語UI
- 再接続: 同じルームコードで再入室したピアに最新スナップショットを再送して復帰
- ホスト切断: 全ゲストに「ゲーム続行不能」を通知して終了（v1はホスト移譲なし — D5）
- `src/core/**` は変更禁止。`src/driver/types.ts` の interface 変更は「既存 LocalDriver/UI が壊れない後方互換の拡張」のみ可（変更した場合は報告に明記）
- Trystero の strategy はデフォルト（nostr/mqtt/torrent いずれか）でよいが、GitHub Pages（静的・HTTPS）で動くこと。独自シグナリングサーバーの導入は禁止
- ロビーUI: 「ホットシート」「ルーム作成（通信対戦）」「ルーム参加」の3導線。通信対戦では作成時に人数上限・ラウンド数を設定し、待機ルームで参加者一覧→ホストが開始

## エッジケース（転写 — 対応箇所を報告で示すこと）
- E1 境界値: 2人と6人 / 満員ルームへの参加拒否 / 存在しないルームコード入力（無応答タイムアウト表示）/ 対局開始後の途中参加は拒否（観戦なし）
- E2 状態遷移: ゲストの不正・二重アクション要求はホストのエンジン検証で拒否し要求元にのみエラー通知 / 開始前のゲスト離脱で待機ルーム一覧更新 / 対局中のゲスト切断→再入室で復帰（切断中は自動パス等はせずホスト権威のタイマーのみ進行）
- E3 時間・並行性: 鳴きウィンドウ中の複数ピア同時宣言はホスト到着順ではなく**エンジンの優先順**（ポン優先・近い方優先）で解決。ウィンドウ満了と宣言の競合はホスト側で直列化 / スナップショットの順序保証（連番を振り古い到着を破棄）
- E5 プリモーテム: 「画面がズレた」→ 全アクション後にスナップショット配信で常に収束 / 「他人の手札がDevToolsで見えた」→ ネットワークペイロードに他家手札が含まれないことをコードとテストで保証 / 「公共シグナリングが落ちて入室できない」→ 接続失敗時に日本語でリトライ案内 / 「タブを閉じたらホストが消えた」→ D5通知の動作確認
- （実装前にタスク固有の追加エッジケースを En+1.. として追補せよ）
