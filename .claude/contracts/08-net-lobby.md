## 目的
- 要求（ユーザー原文）: ①「パスコードを共有するために一度ラインなどに画面を変えると部屋が閉じるのか他のプレイヤーが入れなくなる」②「ルームを作る時に人数指定せず、ゲーム開始時に確定するかたちにしたい」③「そもそもロビーを作れるようにできませんかね？」→ 公開ルーム一覧方式で確定
- ゴール: 招待〜集合の体験を「LINEに切り替えても壊れない・コード入力なしでも集まれる」水準へ
- 成功条件: 合格基準の全コマンド exit 0 + 4項目の個別目視確認報告（status行必須）

## 実装要求（4点）
1. **バックグラウンド耐性**: document の visibilitychange（+ pagehide/pageshow, online）で復帰検知し、トランスポート再join・名簿再アナウンス・（ホストなら）最新スナップショット再送を自動実行。待機ルーム中のホスト離脱→復帰でゲストが再び参加できること。復帰不能な完全停止ケースに備え、待機ルームに「モバイルで画面を切り替えると一時的に部屋が見えなくなることがあります。戻れば自動復帰します」等の控えめな案内
2. **人数の開始時確定**: ルーム作成UIから人数選択を撤去（席上限6は内部定数）。待機ルームは「参加者 n/6」表示。ホストの「対局開始」で現在の名簿人数（2以上）に確定。net の maxPlayers 前提（満員拒否・startのplayers構成）を整合
3. **公開ルーム一覧ロビー**: 作成時に「公開ルームにする」トグル（既定OFF）。ONの部屋は固定ロビーチャネル（例: room='LOBBY' 相当の予約コード — 通常コード空間と衝突しない設計に）へ {code, hostName, count, rounds} を定期広告（数秒間隔）し、閉室/開始/満員で広告停止。ロビー画面に公開ルーム一覧（リアルタイム更新・古い広告のTTL失効）を表示しワンタップ参加。**広告ペイロードに上記4項目以外を載せない**
4. **共有導線**: 待機ルームに「共有」ボタン — navigator.share（room URL `origin/path?room=CODE` + 誘い文）、非対応環境はクリップボードコピー+トースト。アプリ起動時に `?room=CODE` があれば名前入力（保存済みなら自動）→参加フローへ直行

## 不変条件（違反=不合格）
- ホスト権威・視界フィルタ（E5: 他家手札・山札内容をワイヤに載せない）を維持。既存 net テストの当該保証を壊さない
- ゲーム中のプロトコル互換は自由に変えてよい（後方互換不要 — 全員が同一デプロイを使う）が、なりすまし拒否(E7)・二重接続張替え(E8)・スナップショット連番(E3)の性質は維持しテストも更新
- 公開ロビーの広告に個人情報・手札情報を含めない

## エッジケース
- E1: 公開ルームが開始/解散したら一覧から消える（TTL）/ 同時に多数の公開ルーム / 参加直前に満席化（6人）→ 失敗を日本語表示
- E2: `?room=` の不正コード / 保存名なしでURL参加（名前入力を挟む）
- E3: visibilitychange 復帰が接続生存中に発火しても二重joinしない（冪等）
- E4: ロビーチャネル自体の接続失敗はゲーム機能に影響させない（公開一覧だけ空表示）
